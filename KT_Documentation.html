📋 1. Project Overview & Business Value

Why the Flaky Test Detector was built and the core problems it solves.

In modern CI/CD pipelines, flaky tests (tests that intermittently pass and fail on identical source code) are the #1 contributor to developer frustration, false alarms, and bloated release cycles. Traditional test reporters treat test failures as binary, forcing QA teams to manually re-run entire suites or guess whether a failure represents a genuine regression or a transient timing glitch.

⚡
Transition-Based Scoring
Quantifies flakiness strictly based on status flips (Pass ↔ Fail) across sequential historical executions rather than raw pass rates.
🧠
Vector Semantic Search
Indexes error messages and stack traces into Qdrant to find recurring cluster patterns across disparate test files and execution shards.
🎯
Actionable AI Fixes
Uses Groq Llama 3.1 8B to generate pinpointed code-level remediation syntax (Playwright locators, explicit waits, session fixes) rather than generic advice.
💡
Key Distinction: A test failing 100% of the time is NOT flaky — it is a Real Bug / Genuine Regression. A test is only categorized as Flaky if it exhibits flip-flopping non-deterministic transitions over time.

📊 3. Flakiness Scoring & Step Variance Logic

Mathematical formulation for flakiness scores, step variance, and verdict assignment.

1. Transition-Based Flakiness Score Formula

Rather than calculating failCount / totalRuns (which incorrectly labels broken tests as flaky), our algorithm sorts chronological runs for a specific test and counts the number of state transitions:

Mathematical Logic (Python / JS Equivalent)
def calculate_flakiness_score(runs: List[TestRun]) -> float:
    # Requires at least 3 sequential runs to establish pattern
    if len(runs) < 3:
        return 0.0
    
    # Sort chronologically
    sorted_runs = sorted(runs, key=lambda r: r.timestamp)
    transitions = 0
    
    for i in range(1, len(sorted_runs)):
        # Increment if status flips (pass -> fail OR fail -> pass)
        if sorted_runs[i].status != sorted_runs[i-1].status:
            transitions += 1
            
    # Normalize score between 0.0 (0%) and 1.0 (100%)
    return transitions / (len(sorted_runs) - 1)

2. Verdict Classification Rules

VerdictBadge ColorConditionExplanation
Healthy / Stable 🟢 Green failCount === 0 Test has 100% pass record across all monitored runs.
Likely Flaky 🟡 Amber passCount > 0 AND failCount > 0 Test exhibits status flips. Non-deterministic timing, network, or environment issue.
Likely Real Bug 🔴 Red passCount === 0 AND failCount > 0 Test fails consistently (100% fail rate). Points to genuine code regression or offline service.

3. Step Variance Analysis

When multiple failures occur, the engine groups failures by step name or stack trace line to measure variance:

  • Low Variance (≥75% at one step): "Failures are concentrated at one step" → Suggests a localized locator timeout, specific API failure, or missing element.
  • High Variance (<75% at top step): "Failures occur at different steps each time" → Suggests environment degradation, network latency jitter, or systemic auth token loss.

🤖 4. AI Root-Cause Engine & Prompt Engineering

How Groq Llama 3.1 8B produces grounded, tool-specific code fixes.

The analyzer feeds the failed test name, error message, stack trace, and top 5 vector similarity matches into Groq's llama-3.1-8b-instant with a strict persona prompt:

LLM Prompt Template (backend/src/services/root_cause_analyzer.py)
SYSTEM_PROMPT = """You are a senior QA automation engineer.
Analyze the provided test failure and output JSON with:
1. "verdict": "likely_flaky" or "likely_real_bug"
2. "root_cause_category": "timing/race_condition" | "environment" | "network" | "test_data" | "genuine_regression" | "unknown"
3. "explanation": 2-3 sentences explaining why.
4. "actionable_recommendation": Concrete code-level syntax fix tailored to the test automation tool.
   - If Playwright: suggest specific locator waits e.g. await page.locator('#btn').waitFor({ state: 'visible' })
   - If Selenium: suggest explicit WebDriverWait e.g. WebDriverWait(driver, 10).until(...)
   - If Tosca: suggest WaitOn property configuration on Module attribute.
"""

📥 6. Ingestion Pipeline & Multi-Framework Support

How Playwright, Selenium, and Tosca feed into the detector without tag clutter.

1. Automatic Tag Annotation Cleaner

Test runners frequently append tags like @demo, @smoke, or @p1 to test titles. The ingestion layer applies clean_test_name() to strip tag suffixes so test names remain clean across all runs:

Tag Stripping Implementation (tools/junit_xml_to_ingest.py & backend/src/services/junit_parser.py)
def clean_test_name(name: str) -> str:
    """
    Strips trailing Playwright tag annotations e.g.:
    'checkout_submit_button_race_condition @demo' -> 'checkout_submit_button_race_condition'
    'login_test @demo @smoke' -> 'login_test'
    """
    if not name:
        return name
    return re.sub(r'(?:\s+@[\w-]+)+$', '', name).strip()

☁️ 7. Render Deployment & 24/7 Keep-Awake

How the backend is configured on Render Free Tier with zero cold-starts.

1. Render Configuration & Memory Optimization

  • Memory Footprint: Reduced from ~1.2GB down to ~35MB RAM by removing heavy local PyTorch dependencies and utilizing Groq Cloud API for inference.
  • Persistent Disk: Mounted at /data with environment variable DB_PATH=/data/flaky_test_detector.db. Survived restarts without data loss.
  • One-Time Seed Marker: Checks /data/.seeded flag on startup so real CI test data is never overwritten by sample data.

2. Keep-Awake Cron Schedule (.github/workflows/keep-awake.yml)

Render free tier sleeps after 15 minutes of inactivity. Our scheduled GitHub Actions cron pings /health every 10 minutes:

Keep-Awake Workflow (.github/workflows/keep-awake.yml)
name: Keep Render Backend Awake
on:
  schedule:
    - cron: '*/10 * * * *' # Pings every 10 minutes
  workflow_dispatch: {}

jobs:
  ping-health:
    runs-on: ubuntu-latest
    steps:
      - name: Ping Render Backend
        run: |
          curl -s -o /dev/null -w "%{http_code}" --max-time 20 "https://flaky-test-detector-kbpc.onrender.com/health"
