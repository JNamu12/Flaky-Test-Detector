📋 1. Project Overview & Business Value

Why the Flaky Test Detector was built and the core problems it solves.

In modern CI/CD pipelines, flaky tests (tests that intermittently pass and fail on identical source code) are the #1 contributor to developer frustration, false alarms, and bloated release cycles. Traditional test reporters treat test failures as binary, forcing QA teams to manually re-run entire suites or guess whether a failure represents a genuine regression or a transient timing glitch.

⚡
Transition-Based Scoring
Quantifies flakiness strictly based on status flips (Pass ↔ Fail) across sequential historical executions rather than raw pass rates.
🧠
Vector Semantic Search
Indexes error messages and stack traces into Qdrant to find recurring cluster patterns across disparate test files and execution shards.
🎯
Actionable AI Fixes
Uses Groq Llama 3.1 8B to generate pinpointed code-level remediation syntax (Playwright locators, explicit waits, session fixes) rather than generic advice.

📊 4. Flakiness Scoring & Step Variance Math

Detailed mathematical formulas powering the transition score and failure concentration metric.

1. Mathematical Transition Score

The flakiness score $S$ for a test with $N$ chronological executions is calculated as:

$$ S = \frac{1}{N - 1} \sum_{i=2}^{N} \mathbf{1}_{[\text{status}_i \neq \text{status}_{i-1}]} \quad (\text{for } N \ge 3) $$

2. Step Variance Metric

Variance analysis inspects the failure distribution across individual test steps $s \in S$:

  • Concentrated Failure ($\max(Count(s)) / \text{Total Failures} \ge 0.75$): Indicates a specific brittle element locator or target button.
  • Scattered Failure ($\max(Count(s)) / \text{Total Failures} < 0.75$): Indicates systemic worker instability, CPU throttling, or network jitter.

⚙️ 6. CI/CD Workflows Hub

Copy-paste ready GitHub Actions workflow templates supporting all pipelines.

.github/workflows/live-demo-fast.yml (Fast 15-Second Subset)
name: LIVE DEMO — fast subset

on:
  workflow_dispatch:
    inputs:
      reason:
        description: 'Demo run description'
        required: false
        default: 'Live presentation demo'

jobs:
  fast-demo-run:
    name: Run Fast Demo Tests (@demo)
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Node.js 20 & Python 3.11
        uses: actions/setup-node@v4
        with: { node-version: '20' }

      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }

      - name: Install dependencies
        run: |
          npm ci
          npx playwright install chromium --with-deps

      - name: Run Fast Demo Tests (@demo)
        run: |
          mkdir -p results
          npx playwright test --grep @demo --reporter=junit
        continue-on-error: true
        env:
          PLAYWRIGHT_JUNIT_OUTPUT_NAME: results/junit.xml

      - name: Send results to Flaky Test Detector
        if: always()
        env:
          API_KEY: ${{ secrets.DETECTOR_API_KEY }}
        run: |
          DETECTOR_URL="https://flaky-test-detector-kbpc.onrender.com"
          if [ -f results/junit.xml ]; then
            python tools/junit_xml_to_ingest.py results/junit.xml \
              --url "${DETECTOR_URL}/api/v1/test-runs/ingest" \
              --commit-sha "${{ github.sha }}" \
              --api-key "${API_KEY}"
          fi

.github/workflows/keep-awake.yml (24/7 Render Keep-Awake)
name: Keep Render Backend Awake

on:
  schedule:
    - cron: '*/10 * * * *' # Executes every 10 minutes
  workflow_dispatch: {}

jobs:
  ping-health:
    runs-on: ubuntu-latest
    steps:
      - name: Ping Render Backend
        run: |
          URL="https://flaky-test-detector-kbpc.onrender.com/health"
          STATUS=$(curl -s -o /dev/null -w "%{http_code}" --max-time 20 "${URL}" || echo "FAILED")
          echo "Render Health Status: ${STATUS}"

☁️ 10. Render Deployment & 24/7 Keep-Awake

🛠️ 12. QA & Troubleshooting Log

Common questions, edge cases, and architectural fixes resolved during development.

Issue ObservedRoot CauseResolution Applied
Render 502 Bad Gateway / OOM SentenceTransformers loaded PyTorch models exceeding 512MB RAM free limit. Removed local PyTorch; switched to Groq Cloud API and optimized Docker container to ~35MB RAM.
Real Data Lost on Restart Default SQLite path was in container ephemeral storage and seed script ran on every boot. Mounted persistent volume at /data and added one-time .seeded guard file.
Timestamp Showed 02:13 Instead of 07:44 Browser parsed UTC string without explicit 'Z' as naive local time. Implemented parseUTCDate() to enforce UTC parsing before converting to browser local time.
Tag '@demo' Appeared in Test Names Playwright tags in test title were ingested literally. Created regex cleaner re.sub(r'(?:\s+@[\w-]+)+$', '', name) in parser layer.
User Had to Scroll Down to View Analysis Detail panel was placed at bottom of 100+ row table. Transformed panel into modern right-side fixed slide-over drawer with backdrop blur.
Render Slept During Presentations Render Free Tier spins down after 15 minutes of zero traffic. Added keep-awake.yml GitHub Actions workflow to ping /health every 10 minutes.
